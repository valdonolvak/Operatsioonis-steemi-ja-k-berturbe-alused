Toitekatkestus keset muudatust: logi ja kirjutamisel kopeerimine

Animatsioon võrdleb, kuidas NTFS (New Technology File System) ja ext4 (logi) ning APFS (Apple File System), Btrfs ja ReFS (Resilient File System; kirjutamisel kopeerimine) jäävad terveks, kui toide katkeb poole muudatuse pealt.

Sammud

Mõisted

MõisteSelgitus
Kooskõla (consistency)Failisüsteemi struktuurid ei räägi üksteisele vastu: iga hõivatud plokk kuulub mõnele failile ja iga faili plokid on hõivatuks märgitud.
Tehing (transaction)Rühm muudatusi, mis peavad toimuma kas kõik või mitte ükski.
Logi (journal)Kettaala, kuhu tehing kirjutatakse enne päris muudatusi. NTFS-is $LogFile, ext4-s journal.
Kinnitamine (commit)Märge logis, et tehing on täielikult kirja pandud ja selle võib pärast krahhi lõpule viia.
Logi taasesitus (replay)Taaskäivitusel loetakse logi: kinnitatud tehingud viiakse lõpule, kinnitamata visatakse ära.
Vabade plokkide kaartBitikaart, kus iga bitt ütleb, kas plokk on vaba või hõivatud. NTFS-is $Bitmap.
Kirjutamisel kopeerimine (copy-on-write, CoW)Olemasolevat plokki ei kirjutata üle. Muudetud versioon läheb vabasse kohta ja seejärel lülitatakse viit.
AatomilineToiming, millel ei ole vahepealset olekut: see kas toimus täielikult või ei toimunud üldse.
Hetktõmmis (snapshot)Failisüsteemi seis ühel ajahetkel. Kopeerivas failisüsteemis piisab selleks vana viida allesjätmisest.
KloonFaili koopia, mis viitab esialgu samadele plokkidele kui originaal (APFS, ReFS, Btrfs-i ja XFS-i reflink).
chkdsk, fsckTööriistad, mis kontrollivad kogu failisüsteemi kooskõla. Logita failisüsteemis tuli neid käivitada pärast iga krahhi.

Proovi ise

Windows (PowerShell administraatorina)

fsutil dirty query C:
fsutil fsinfo ntfsinfo C:
fsutil usn queryjournal C:
chkdsk C: /scan
  • 1. rida: küsi, kas köide on märgitud „mustaks“ (dirty). Must köide tähendab, et Windows kahtlustab vastuolu ja kontrollib köidet järgmisel käivitusel.
  • 2. rida: näita NTFS-i üldandmeid: klastri suurus, MFT (Master File Table) asukoht ja suurus.
  • 3. rida: näita muudatuste päeviku (USN Journal (USN – Update Sequence Number)) olekut. See ei ole sama mis $LogFile: USN-päevik ütleb programmidele, millised failid muutusid.
  • 4. rida: kontrolli köite kooskõla töö ajal, midagi parandamata.

Mida otsida: tavaolukorras vastab esimene käsk „Volume – C: is NOT Dirty“ ja chkdsk ei leia vigu, sest logi hoiab struktuuri korras ka pärast ootamatut väljalülitamist.

Linux (terminal)

findmnt -no FSTYPE,OPTIONS /
sudo dumpe2fs -h $(findmnt -no SOURCE /) | grep -i journal
sudo journalctl -k | grep -i 'EXT4-fs'
  • 1. rida: näita juurfailisüsteemi tüüpi ja ühendamise valikuid.
  • 2. rida: loe ext4 ülemploki päis ja näita logi puudutavaid ridu. findmnt -no SOURCE / annab seadme nime, näiteks /dev/sda2.
  • 3. rida: otsi tuuma logist ext4 teateid.

Mida otsida: teises väljundis rida has_journal ja logi suurus. Kui arvuti lülitati eelmisel korral välja toitenupust, on kolmandas väljundis rida „recovery complete“: see ongi logi taasesitus. Kui juurfailisüsteem ei ole ext4, annab teine käsk vea.

macOS (Terminal)

tmutil localsnapshot
tmutil listlocalsnapshots /
diskutil apfs listSnapshots /
  • 1. rida: tee kohe kohalik hetktõmmis.
  • 2. rida: näita juurköite kohalikke hetktõmmiseid.
  • 3. rida: näita samu hetktõmmiseid APFS-i vaates koos tunnustega.

Mida otsida: hetktõmmis tekib kohe ja ei võta alguses ruumi, sest see on ainult viit olemasolevatele plokkidele.
