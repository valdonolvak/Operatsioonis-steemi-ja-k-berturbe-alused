Paigaldus üle võrgu: Windowsi WDS ja Linux kõrvuti

Animatsioon võrdleb seitsme sammu kaupa, kuidas võrgust käivitatud arvutisse paigaldatakse automaatselt Windows (WDS) ja Linux (Debiani võrgupaigaldus).

WDS-i seis 2026. aastal

Microsoft on WDS-i järk-järgult kõrvale jätmas ja see mõjutab otseselt siin näidatud töövoogu:

  • Windows 11 paigalduskandjalt võetud boot.wim-iga WDS-i paigaldust ei toetata; ainult WDS-iga ei saa Windows 11 algusest lõpuni paigaldada. Kohandatud alglaadimistõmmised (näiteks Configuration Manageri omad) töötavad edasi.
  • Alates 2026. aasta aprilli uuendustest on käed-vabad paigaldus (vastusfaili saatmine WDS-ist) vaikimisi välja lülitatud turvanõrkuse CVE-2026-0386 tõttu.
  • 2026. aasta septembris teatas Microsoft, et WDS-i roll tervikuna jääb alates järgmisest Windows Serveri väljaandest aegunute hulka. Praegu toetatud serveriversioonides töötab WDS edasi.

Õppelaboris sobib WDS endiselt PXE ja tõmmisepõhise paigalduse põhimõtete näitamiseks. Uue lahenduse kavandamisel loe enne Microsofti juhiseid: WDS boot.wim support ja KB5129631.

Proovi ise

WDS-serveris (PowerShell administraatorina)

Get-WindowsFeature WDS*
wdsutil /Get-Server /Show:Config
Get-WdsBootImage | Select-Object ImageName, Architecture, FileName
Get-WdsInstallImage | Select-Object ImageName, ImageGroup, Version
Get-WdsClient
  • 1. rida: näita, kas WDS-i roll ja selle osad (Deployment Server, Transport Server) on paigaldatud.
  • 2. rida: näita serveri seadistust: kellele PXE vastab (kõigile, ainult tuntud klientidele või mitte kellelegi), kus on kaust RemoteInstall ja millised alglaadurid on määratud.
  • 3. rida: loetle alglaadimistõmmised koos arhitektuuri ja failinimega.
  • 4. rida: loetle paigaldustõmmised, nende rühm ja Windowsi versioon.
  • 5. rida: loetle eelregistreeritud klientarvutid.

Mida otsida: teise käsu väljundis jaotis „PXE Bind Policy“ ja „Answer clients“. Kui seal on „Answer clients: No“, ei vasta server ühelegi kliendile, kuigi teenus töötab.

Linuxi PXE-server: dnsmasq

Fail /etc/dnsmasq.d/pxe.conf:

interface=ens19
dhcp-range=192.168.10.100,192.168.10.200,12h
enable-tftp
tftp-root=/srv/tftp
dhcp-match=set:efi64,option:client-arch,7
dhcp-boot=tag:efi64,shimx64.efi
dhcp-boot=tag:!efi64,pxelinux.0
  • 1. rida: teeninda ainult seda võrguliidest (labori sisevõrk).
  • 2. rida: jaga aadresse vahemikust .100 kuni .200, rendiaeg 12 tundi.
  • 3.–4. rida: lülita sisse dnsmasqi enda TFTP-server ja määra kaust, kust faile jagatakse.
  • 5. rida: kui klient saadab valikus 93 väärtuse 7 (x64 UEFI), anna talle silt efi64.
  • 6. rida: sildiga efi64 klient saab alglaaduriks shimx64.efi.
  • 7. rida: kõik teised (vana BIOS) saavad pxelinux.0.

Selles näites jagab dnsmasq ka IP-aadresse. Ära käivita seda võrgus, kus on juba teine DHCP-server.

Menüükirje failis /srv/tftp/grub/grub.cfg:

menuentry 'Debian: automaatne paigaldus' {
    linux  /debian-installer/amd64/linux auto=true priority=critical url=http://192.168.10.1/preseed.cfg
    initrd /debian-installer/amd64/initrd.gz
}
  • 1. rida: menüüs näidatav nimi.
  • 2. rida: laadi tuum ja anna talle parameetrid: auto=true lükkab küsimused edasi, kuni võrk töötab; priority=critical jätab vahele kõik vähem tähtsad küsimused; url= on vastusfaili aadress.
  • 3. rida: laadi algne failisüsteem, milles on paigaldaja.
sudo systemctl restart dnsmasq
sudo journalctl -u dnsmasq -f

Esimene käsk rakendab seadistuse, teine näitab dnsmasqi logi jooksvalt. Käivita klient võrgust. Mida otsida: read DHCPDISCOVER, DHCPOFFER, DHCPACK ja seejärel sent /srv/tftp/shimx64.efi to 192.168.10.x. Kui pärast DHCPACK-i rida sent ei tule, ei leidnud klient faili või blokeerib tulemüür TFTP.
